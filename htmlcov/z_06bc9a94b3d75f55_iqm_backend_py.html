1"""The IQM backend, which runs circuits on IQM quantum computers through iqm-client. 

2 

3The `iqm-client` package, with its `qiskit` extra, is an optional dependency 

4(`pip install eigenkit[iqm]`). It is imported only when it is needed, so the rest of 

5the library works without it. If it is missing, `compile()` raises an `ImportError` 

6with a clear message. 

7 

8This backend connects directly to IQM Resonance, or to any IQM Server, instead of 

9using the same hardware through Amazon Braket. You then pay through IQM's own plans 

10instead of an Amazon Web Services (AWS) bill. It is also the only way to reach IQM's 

11fake backends, its calibration sets and its architectures with `MOVE` gates. 

12 

13IQM has **no estimator primitive**: the IQM service returns histograms of measured 

14bitstrings and nothing else. So this backend works by sampling everywhere. The 

15observables are sorted into groups of qubit-wise commuting terms, one circuit runs 

16for each group, and the expectation values are computed locally from the counts 

17(see the `_sampling` module). `probabilities()` and `sample()` use the same code, 

18and this is what lets the quantum approximate optimisation algorithm (QAOA) read a 

19solution from real hardware. 

20 

21There are two kinds of target: 

22 

23- **Resonance or any IQM Server**: pass `url` and a `token` (or set the `IQM_TOKEN` 

24 environment variable). You can also pass `quantum_computer` to choose one machine 

25 when the server hosts several. 

26- **Local fake backends**: pass `IQMFakeAdonis()`, `IQMFakeApollo()`, 

27 `IQMFakeDeneb()` or a similar fake backend as `backend_instance`. These run on 

28 Qiskit Aer with a realistic IQM noise model, with no token and no network access. 

29 The tests of this backend run on them. 

30 

31The default is `gradient_method = "none"`, because hardware is too expensive for 

32parameter-shift gradients: one backward pass takes at least `2 * n_weights` jobs, 

33each with the full number of shots. Train on a simulator, then use the trained 

34weights on the device. `enable_gradients=True` in the configuration turns on 

35parameter-shift gradients on the device. Compiling for a real device then issues a 

36`CostWarning` that gives the number of circuits of one backward pass. 

37 

38The circuits are transpiled for the device target. The native gates are `r` and 

39`cz`, and also `move` on the Star architectures, which the Qiskit transpiler routes 

40through the plugin that iqm-client provides. `transpile_mode` chooses when this 

41happens: 

42 

43- `"parametric"`, the default, transpiles once for each measurement group and sets 

44 the parameter values at each call. This is cheap, but the transpiler cannot merge 

45 rotations whose angles it does not know. For example, an encoding block and a 

46 variational block on 2 qubits, measured in one group, gave 6 `r` gates in this 

47 mode against 3 with the values set before transpiling. 

48- `"per_call"` sets the values first and transpiles at every call. The circuits are 

49 shallower, so they run with higher fidelity on hardware. The cost is one 

50 transpilation per evaluation, which is small next to the time spent in the queue, 

51 but not next to a local simulator. 

52 

53Example: 

54 ```python 

55 from eigenkit import Circuit, Encoding, Variational, all_z 

56 from eigenkit.configs import IQMConfig 

57 

58 blocks = [Encoding(in_features=4), Variational(depth=2)] 

59 

60 # Offline, against IQM's noise-modelled fake backend. 

61 from iqm.qiskit_iqm import IQMFakeAdonis 

62 

63 circuit = Circuit( 

64 blocks=blocks, 

65 observables=all_z(4), 

66 provider=IQMConfig(backend_instance=IQMFakeAdonis(), shots=2048), 

67 ) 

68 

69 # On real hardware, by name. 

70 circuit = Circuit( 

71 blocks=blocks, 

72 observables=all_z(4), 

73 provider=IQMConfig( 

74 url="https://resonance.iqm.tech/", 

75 quantum_computer="garnet", 

76 shots=2048, 

77 ), 

78 ) 

79 ``` 

80 

81 The backend is registered as `"iqm"` when the `iqm` extra is installed, and its 

82 module is imported only when it is first used. A real device uses your IQM 

83 quota: the first compilation for a real device issues a `CostWarning`, and 

84 `dry_run_info()` reports the size of the circuit and the number of circuits 

85 that each call submits, before you submit anything. 

86"""

143 

144 There are two ways to choose a target: 

145 

146 - `url`, and optionally `quantum_computer`, opens an `IQMProvider` for an IQM 

147 Server. This needs a token, from `token` or from the `IQM_TOKEN` environment 

148 variable. 

149 - `backend_instance` uses any IQM `BackendV2` directly: a fake backend for 

150 offline work, or a backend that you configured yourself. It takes precedence 

151 over `url`, and it needs no token and no network access. 

152 

153 Args: 

154 url: The address of the IQM Server, for example 

155 `"https://resonance.iqm.tech/"`. It is ignored when `backend_instance` 

156 is set. With `None`, the backend reads the address from the 

157 `IQM_SERVER_URL` environment variable when the circuit is compiled. 

158 quantum_computer: The machine to use when the server hosts more than one, 

159 for example `"garnet"`. With `None`, the server's default is used. 

160 backend_instance: An IQM backend that is already configured. It takes 

161 precedence over `url`. 

162 shots: The number of shots for each circuit run. It must be positive, 

163 because hardware cannot compute exact values. 

164 optimization_level: The optimisation level passed to `qiskit.transpile`, 

165 from `0` to `3`. 

166 seed_transpiler: The seed of the random steps of the transpiler, mainly 

167 the `SabreLayout` and `SabreSwap` passes, which choose the layout and 

168 the routing. With `None`, the default, a new seed is drawn for every 

169 compilation, so a circuit that needs routing compiles to a different 

170 number of gates on every run. Within one compilation, all the 

171 transpilations share the seed, including those of the shifted copies 

172 that a hardware gradient compiles. Set it whenever two compilations 

173 must be comparable. Trying a few seeds and keeping the cheapest result 

174 is a cheap and fair way to choose a layout, because compiling submits 

175 nothing. 

176 transpile_mode: `"parametric"` transpiles once and sets the parameter 

177 values at each call. `"per_call"` sets the values first and transpiles 

178 at every call, which gives shallower circuits but costs one 

179 transpilation per evaluation. 

180 group_commuting: Whether to put Pauli terms that commute qubit by qubit 

181 into shared measurement circuits. With `False`, one circuit runs for 

182 each term: there are more jobs, but each term gets all the shots. 

183 token: The access token for the IQM Server. It is passed on only when it 

184 is set. With `None`, iqm-client handles authentication on its own, 

185 from `IQM_TOKEN` and from its own tokens file. Do not set both `token` 

186 and `IQM_TOKEN`, because iqm-client rejects a token given in two ways 

187 at once. This field is secret: `repr()` never shows it, and it is never 

188 saved in `.eigenkit` bundles, pickles or joblib checkpoints. After a 

189 load it is `None`, so set `IQM_TOKEN`. 

190 calibration_set_id: The calibration set to use, as a `UUID`. With `None`, 

191 the server's default is used. 

192 use_metrics: Whether to ask the server for the error rates of each qubit 

193 and each coupler, and load them into the `InstructionProperties` of 

194 the target. With `False` (the default of iqm-client itself), the 

195 target has no error rates, so the Qiskit layout pass does not see the 

196 noise. It then cannot prefer the better qubits, and a comparison with 

197 a backend that *does* have calibration data is not like for like. It 

198 costs one extra request at compile time, and it is ignored when 

199 `backend_instance` is set. 

200 provider_kwargs: Extra keyword arguments passed to `IQMProvider`, for 

201 example `tokens_file`. 

202 poll_timeout_seconds: How many seconds `result()` waits before giving up. 

203 enable_gradients: Whether to allow parameter-shift gradients on the 

204 device, for PyTorch `.backward()`, `jacobian()` and gradient-based 

205 optimisers. It is off by default, because one backward pass runs the 

206 circuits of a forward call at least `2 * n_weights` times. When it is 

207 set, compiling for a real device issues a `CostWarning` that gives 

208 this count. 

209 """

314def _error_profile_success_probability(circuit, backend) -> float | None: 

315 """Estimated success probability from an IQM fake backend's error profile. 

316 

317 IQM's fake backends leave the Qiskit target without error rates, but carry 

318 them in `error_profile` as depolarizing parameters `lambda`, keyed by qubit 

319 name. A depolarizing channel on `d` levels has average infidelity 

320 `lambda * (d - 1) / d`; readout contributes the mean of its two 

321 misassignment rates. `None` when the backend has no profile. 

322 """ 

323 profile = getattr(backend, "error_profile", None) 

324 if profile is None: 324 ↛ 325line 324 didn't jump to line 325 because the condition on line 324 was never true

325 return None 

326 single = profile.single_qubit_gate_depolarizing_error_parameters 

327 double = profile.two_qubit_gate_depolarizing_error_parameters 

328 readout = profile.readout_errors 

329 probability = 1.0 

330 for instruction in circuit.data: 

331 name = instruction.operation.name 

332 try: 

333 qubits = [ 

334 backend.index_to_qubit_name(circuit.find_bit(q).index) 

335 for q in instruction.qubits 

336 ] 

337 except Exception: # noqa: BLE001 — an unnamed wire carries no error rate 

338 continue 

339 if name == "measure": 

340 rates = readout.get(qubits[0]) 

341 if rates: 

342 probability *= 1.0 - 0.5 * (rates.get("0", 0.0) + rates.get("1", 0.0)) 

343 continue 

344 key = _ERROR_PROFILE_GATES.get(name) 

345 if key is None: 

346 continue 

347 if len(qubits) == 1: 

348 lam, levels = single.get(key, {}).get(qubits[0]), 2 

349 else: 

350 table = double.get(key, {}) 

351 lam = table.get(tuple(qubits), table.get(tuple(reversed(qubits)))) 

352 levels = 4 

353 if lam is not None: 

354 probability *= 1.0 - float(lam) * (levels - 1) / levels 

355 return probability
