1"""The provider protocol, its registry, and the parameter-shift fallback. 

2 

3A provider compiles a circuit separately from running it, which matters for 

4speed. Building a `qml.device` and a QNode (PennyLane), or a parametrised 

5`QuantumCircuit` and a `SparsePauliOp` (Qiskit), takes far longer than one 

6execution. Doing that work once per `Circuit` and reusing the compiled handle for 

7every forward pass is what makes repeated evaluations fast. 

8 

9The `run` and `run_torch` methods of each backend accept batched arrays 

10directly. The first axis is the batch, and `weights` and `inputs` can each be 1-D 

11(one sample) or 2-D (a batch). Backends that can run a batch at once override 

12`run` to submit one job. The others call `batch_call` and pay for a loop in 

13Python, but the loop is inside the backend and not in the `Circuit` that calls 

14it. The `Capabilities.supports_batching` flag only gives information, and 

15nothing chooses a path based on it: `Circuit` always passes the batch on 

16unchanged. 

17 

18Example: 

19 ```python 

20 from eigenkit.core.provider import get, registered_names 

21 

22 print(registered_names()) # ['numpy'] when no extra is installed 

23 

24 backend = get("numpy") 

25 print(backend.gradient_method) # adjoint 

26 print(backend.capabilities.supports_batching) # True 

27 ``` 

28"""

128@dataclass(frozen=True) 

129class Capabilities: 

130 """The description that a provider gives of what it supports. 

131 

132 It is used to check a circuit before compilation, and to choose between code 

133 paths at run time. 

134 

135 Attributes: 

136 supported_gates: The names of the gates that the backend can run. A circuit 

137 that uses any other gate is rejected before compilation, with a message 

138 that names that gate. 

139 supports_batching: Whether the backend evaluates a 2-D `inputs` batch in 

140 one call, instead of looping over it internally. It only gives 

141 information: `Circuit` passes the batch on in both cases and never 

142 reads this flag. It describes the strategy of the backend, and nothing 

143 chooses a path based on it.

145 expectation values.

151 be extracted. Iterative quantum amplitude estimation (IQAE) uses this 

152 to accept oracles that are PennyLane callables.

154 with its own shots, which is what IQAE needs for 

155 `shot_mode="provider"`. 

156 """ 

157 

158 supported_gates: frozenset[str] 

159 supports_batching: bool 

160 supports_shots: bool 

161 max_qubits: int | None = None 

162 supported_adjoint_gates: frozenset[str] | None = None

247# ---- registry and provider resolution ---- 

248# 

249# `provider=` on the user-facing Circuit accepts three shapes: 

250# str - looked up in the registry ("pennylane"/"qiskit" pre-registered) 

251# Config - any object with a `make_backend()` factory (e.g. PennyLaneConfig) 

252# Backend - a Provider instance, used directly 

253# 

254# Registration is optional aliasing: register a config or backend under a 

255# short name when you want to reuse it. The zero-config and inline-config 

256# paths never touch the registry. 

257 

258 

259_REGISTRY: dict[str, Provider] = {} 

260# Lazy entries: `name -> loader()` that imports the backend's SDK and returns 

261# a Provider only when the name is first resolved. This is what keeps 

262# `import eigenkit` (and `eigenkit.core`) from pulling 

263# torch / pennylane / qiskit — those SDKs load on first use, not on import. 

264_LAZY: dict[str, Callable[[], Provider]] = {} 

265

268 """Register a backend, or a configuration that can build one, under `name`. 

269 

270 Later calls to `Circuit(..., provider=name)` then use that backend. If a 

271 configuration is passed, its `make_backend()` method is called to build the 

272 backend. 

273 

274 Args: 

275 name (str): The name to register. 

276 provider_or_config (Provider | object): A backend instance, or a 

277 configuration with a `make_backend()` method. 

278 """ 

279 _REGISTRY[name] = _materialize(provider_or_config) 

280 _LAZY.pop(name, None)

283def register_lazy(name: str, loader: Callable[[], Provider]) -> None: 

284 """Register a backend under `name` without importing its package yet. 

285 

286 `loader` is called the first time the name is looked up, and its result is 

287 kept for later lookups. The optional backends are registered in this way, so 

288 that naming them imports nothing. 

289 

290 It replaces whatever `name` currently refers to, as `register` does. If the 

291 registration were skipped when the name was already taken, a caller could not 

292 replace a built-in backend with a lazy one, and would get no sign that the 

293 loader had been ignored. 

294 

295 Args: 

296 name (str): The name to register. 

297 loader (Callable[[], Provider]): A function with no arguments that returns 

298 the backend. It is called the first time the name is looked up. 

299 """ 

300 _LAZY[name] = loader 

301 _REGISTRY.pop(name, None)

350def get(name: str) -> Provider: 

351 """Return the provider registered under `name`. 

352 

353 A backend registered with `register_lazy` imports its package at the first 

354 lookup, and the backend is kept for later lookups. 

355 

356 Args: 

357 name: A registered short name, such as `"numpy"` or `"pennylane"`. 

358 

359 Returns: 

360 The provider instance. 

361 

362 Raises: 

363 ImportError: If `name` is a registered backend whose package is not 

364 installed, or is installed but fails to import. For a missing 

365 package the message names the extra that installs it. The 

366 registration is kept, so a later call works once the package is 

367 installed. 

368 KeyError: If nothing is registered under `name`. The message lists the 

369 available names and, for a known backend, the extra that installs it. 

370 """ 

371 if name in _REGISTRY: 

372 return _REGISTRY[name] 

373 if name in _LAZY: 

374 try: 

375 provider = _LAZY[name]() # import the SDK now, then cache 

376 except ImportError as exc: 

377 # Do not drop the registration: `name` is a backend this build 

378 # knows about, it is only missing its package. Popping first would 

379 # make the *second* attempt report the name as unknown, which is a 

380 # different and untrue problem. 

381 if not isinstance(exc, ModuleNotFoundError): 

382 # The package is there but did not load: a missing system 

383 # library, say. Naming the extra would send the user to 

384 # install what they already have. 

385 raise ImportError( 

386 f"provider '{name}' is installed but its package failed to " 

387 f"import{load_failure_hint(exc)}. Original error: {exc}" 

388 ) from exc 

389 hint = _EXTRA_HINT.get(name) 

390 suffix = f" ({hint})" if hint else "" 

391 raise ImportError( 

392 f"provider '{name}' is registered but its package is not " 

393 f"installed{suffix}. Original error: {exc}" 

394 ) from exc 

395 _LAZY.pop(name, None) 

396 _REGISTRY[name] = provider 

397 return provider 

398 hint = _EXTRA_HINT.get(name) 

399 suffix = f" ({hint})" if hint else "" 

400 raise KeyError( 

401 f"no provider registered under name '{name}'{suffix}. " 

402 f"registered: {sorted(registered_names())}. " 

403 f"Pass a config directly (e.g. PennyLaneConfig(...)) to skip registration." 

404 )

446 """Raise a `ValueError` if the circuit cannot run on the provider. 

447

463 capabilities.supported_adjoint_gates 

464 if capabilities.supported_adjoint_gates is not None

494def validate_initial_state( 

495 initial_state, n_qubits: int, *, batch: int | None = None 

496) -> np.ndarray: 

497 """Check and flatten a statevector that the user gives as a starting state. 

498 

499 It returns a contiguous `complex128` array in the flat order of the library, 

500 where qubit `0` is the most significant bit. The shape is `(2**n,)` when 

501 `batch` is `None`, and `(batch, 2**n)` otherwise. A 1-D state passed with a 

502 `batch` is repeated for every row of the batch. It raises a `ValueError` if 

503 the length is wrong or the state is not normalised. A unitary evolution keeps 

504 the norm, so a state that is not normalised is almost always a mistake of the 

505 caller. Each backend reshapes the returned flat array into its own state 

506 layout. Doing the checks here, in one place, keeps the error messages the same 

507 for the NumPy, PennyLane and Qiskit backends. 

508 

509 Args: 

510 initial_state (np.ndarray): The statevector to start from. 

511 n_qubits (int): The number of qubits of the circuit. 

512 batch (int | None): The batch size that the state must match, or `None` 

513 for a single state. Default: `None`. 

514 

515 Returns: 

516 The flattened statevector, after the checks. 

517 """ 

518 arr = np.asarray(initial_state, dtype=np.complex128) 

519 dim = 1 << n_qubits 

520 if batch is None: 

521 arr = arr.reshape(-1) 

522 if arr.shape[0] != dim: 

523 raise ValueError( 

524 f"initial_state must have length {dim} (2**{n_qubits}), " 

525 f"got {arr.shape[0]}" 

526 ) 

527 _check_normalized(arr) 

528 return np.ascontiguousarray(arr) 

529 if arr.ndim <= 1: 

530 single = arr.reshape(-1) 

531 if single.shape[0] != dim: 531 ↛ 532line 531 didn't jump to line 532 because the condition on line 531 was never true

532 raise ValueError( 

533 f"initial_state must have length {dim} (2**{n_qubits}), " 

534 f"got {single.shape[0]}" 

535 ) 

536 _check_normalized(single) 

537 return np.broadcast_to(single, (batch, dim)).copy() 

538 if arr.shape != (batch, dim): 538 ↛ 539line 538 didn't jump to line 539 because the condition on line 538 was never true

539 raise ValueError( 

540 f"batched initial_state must have shape ({batch}, {dim}), got {arr.shape}" 

541 ) 

542 norm_sq = np.einsum("bi,bi->b", arr.conjugate(), arr).real 

543 if not np.allclose(norm_sq, 1.0, rtol=0.0, atol=1e-6): 543 ↛ 544line 543 didn't jump to line 544 because the condition on line 543 was never true

544 raise ValueError("every initial_state row must be L2-normalized") 

545 return np.ascontiguousarray(arr)

566def batch_call( 

567 run_one: Callable[[np.ndarray, np.ndarray], np.ndarray], 

568 weights: np.ndarray, 

569 inputs: np.ndarray, 

570) -> np.ndarray: 

571 """Call `run_one(w_i, x_i)` for each sample along the first (batch) axis. 

572 

573 It is meant for backends that cannot run a batch at once. It holds the loop 

574 over the samples, and if one sample fails, it raises a `RuntimeError` that 

575 gives the index of that sample, so the caller can find which sample failed. 

576 

577 Args: 

578 run_one (Callable): A function that evaluates one sample. 

579 weights (np.ndarray | Sequence[float]): The weights, 1-D for one sample or 

580 2-D for a batch. They must be a NumPy array or a PyTorch tensor, 

581 because the batch is detected from `ndim` and `shape`. A list is not 

582 accepted. 

583 inputs (np.ndarray | Sequence[float]): The inputs, 1-D or 2-D, in the same 

584 kinds of container as `weights`. 

585 

586 Returns: 

587 The results of the samples, stacked. 

588 """ 

589 B, w_is_batch, x_is_batch = _batch_pair(weights, inputs) 

590 if B is None: 

591 return run_one(weights, inputs) 

592 outputs = [] 

593 for i in range(B): 

594 w_i = weights[i] if w_is_batch else weights 

595 x_i = inputs[i] if x_is_batch else inputs 

596 try: 

597 outputs.append(run_one(w_i, x_i)) 

598 except Exception as exc: 

599 raise RuntimeError(f"failed on batch sample index {i}") from exc 

600 return np.stack(outputs) 

601 

602 

603# ---- parameter-shift gradient ---- 

604 

605# The two-term rule df/dtheta = [f(theta + pi/2) - f(theta - pi/2)] / 2 is exact 

606# only when the gate's generator has one eigenvalue gap, so its expectation 

607# carries one frequency. A controlled rotation has two ({1/2, 1}) and needs four 

608# evaluations. These are the standard shifts and coefficients for that spectrum. 

609# The four-term rule is also exact for a single-frequency gate -- {1} sits 

610# inside {1/2, 1} -- so it is only ever a cost question, never a correctness 

611# one; it is used exactly where `ir.MULTI_FREQUENCY_GATES` says it is needed. 

612_SQRT2 = np.sqrt(2.0) 

613FOUR_TERM_RULE: tuple[tuple[float, float], ...] = ( 

614 (np.pi / 2, (_SQRT2 + 1.0) / (4.0 * _SQRT2)), 

615 (-np.pi / 2, -(_SQRT2 + 1.0) / (4.0 * _SQRT2)), 

616 (3 * np.pi / 2, -(_SQRT2 - 1.0) / (4.0 * _SQRT2)), 

617 (-3 * np.pi / 2, (_SQRT2 - 1.0) / (4.0 * _SQRT2)), 

618) 

619TWO_TERM_RULE: tuple[tuple[float, float], ...] = ( 

620 (np.pi / 2, 0.5), 

621 (-np.pi / 2, -0.5), 

622)

625def _shift_column(evaluate, vector: np.ndarray, index: int, four_term: bool): 

626 """One jacobian column: sum of `coefficient * f(vector shifted at index)`. 

627 

628 Args: 

629 evaluate: Callable taking the shifted vector and returning `(n_obs,)`. 

630 vector (np.ndarray): The weights or inputs being differentiated. 

631 index (int): Which entry to shift. 

632 four_term (bool): Use the four-term rule instead of the two-term one. 

633 

634 Returns: 

635 The column, shape `(n_obs,)`. 

636 """ 

637 rule = FOUR_TERM_RULE if four_term else TWO_TERM_RULE 

638 column = None 

639 for shift, coefficient in rule: 

640 shifted = vector.copy() 

641 shifted[index] += shift 

642 term = coefficient * evaluate(shifted) 

643 column = term if column is None else column + term 

644 return column

647def parameter_shift_jacobian( 

648 compiled: CompiledCircuit, 

649 weights: np.ndarray, 

650 inputs: np.ndarray, 

651 four_term_indices: frozenset[int] | None = None, 

652) -> np.ndarray: 

653 r"""Return the jacobian with respect to the weights, by the parameter-shift rule. 

654 

655 Each entry is \(d\langle O_k \rangle / d\theta_i\), computed with the 

656 parameter-shift rule. For a weight whose gates have a single frequency, the rule 

657 takes two evaluations, \((f(\theta + \pi/2) - f(\theta - \pi/2)) / 2\). For a 

658 weight listed in `four_term_indices`, it uses the four-term rule. 

659 

660 Args: 

661 compiled (CompiledCircuit): The prepared circuit to differentiate. 

662 weights (np.ndarray | Sequence[float]): The weight vector, as a NumPy 

663 array or a list. A PyTorch tensor is not accepted, because the vector 

664 is shifted on a copy made with `.copy()`. 

665 inputs (np.ndarray | Sequence[float]): The input vector, in any container 

666 that `compiled.run` accepts: a NumPy array, a PyTorch tensor or a list. 

667 four_term_indices (frozenset[int] | None): The weights that feed a gate 

668 with several frequencies, as returned by 

669 `ir.weights_needing_four_term_shift`. The two-term rule is not exact 

670 for those weights (on a controlled rotation it is wrong by tens of 

671 percent), so leaving them out here returns wrong gradients, not an 

672 error. 

673 

674 Returns: 

675 The jacobian, of shape `(n_observables, n_weights)`. 

676 """ 

677 n_weights = len(weights) 

678 if n_weights == 0: 678 ↛ 680line 678 didn't jump to line 680 because the condition on line 678 was never true

679 # No columns to fill, but the caller still expects the observable axis. 

680 return np.zeros((len(compiled.run(weights, inputs)), 0), dtype=np.float64) 

681 four_term = four_term_indices or frozenset() 

682 # Sized from the first shifted evaluation rather than from a baseline run. 

683 # A baseline is not part of the parameter-shift rule — it would serve only to 

684 # read the observable count — and on a metered or shots backend it would be 

685 # a paid submission per gradient. 

686 jacobian: np.ndarray | None = None 

687 for i in range(n_weights): 

688 column = _shift_column( 

689 lambda shifted: compiled.run(shifted, inputs), weights, i, i in four_term 

690 ) 

691 if jacobian is None: 

692 jacobian = np.zeros((len(column), n_weights), dtype=np.float64) 

693 jacobian[:, i] = column 

694 return jacobian
